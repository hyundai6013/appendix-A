# 새로운 수집의 실행 순서

과거 결과를 확인하려면 `python -m robots_study`를 사용한다. 이 문서의 명령은 새 시점의 관측이다. 웹사이트 설정·응답·약관은 변할 수 있으므로 2026년 7월 수치와 같아야 하는 절차가 아니다.

## robots.txt

저장소 최상위 폴더에서 실행한다. 아래 `python`은 requirements가 설치된 환경의 실행 파일을 뜻한다.

```bash
python collection/robots_collector.py --limit 10 --www-fallback --outdir collection_runs/pilot_01
```

표본 프레임과 수집된 결과를 확인한 뒤 `--limit 10`을 빼면 전체 수집을 실행할 수 있다. `--xlsx`로 사이트 프레임, `--crawlers-xlsx`로 초기 토큰 프레임을 지정할 수 있다. 기본 입력은 저장소의 `data/inputs/master_frame.xlsx`, `crawler_frame.xlsx`다. 필요하면 원본을 수정하지 말고 새 입력 사본을 만든다.

순서는 수집대상 필터 → 도메인 중복 제거 → HTTPS `/robots.txt` 요청 → 응답 원문 저장 → 초기 토큰의 루트 판정이다. 요청 시 일반 브라우저 형식의 User-Agent를 사용한다. TLS 인증서 검증을 비활성화하지 않는다. 연결 예외 때만 `www` 후보를 시도하며, HTTP 응답을 이미 받았다면 상태가 실패여도 해당 후보에서 종료한다. 리다이렉트는 따른다.

200 응답을 UTF-8 텍스트로 저장한다. 404·410은 파일 부재로, 나머지 HTTP 오류나 연결 실패는 판독 불가로 기록한다. 사이트 사이 기본 대기값은 1~2초이며, 리다이렉트·호스트 후보 시도 등을 포함한 모든 HTTP 요청이 각각 이 간격을 갖는 것은 아니다. 타임아웃·대기 설정은 `--help`에서 확인한다.

재시도하려면 실패 도메인만 들어 있는 프레임 사본을 `--xlsx`에 지정하고 새 `--outdir`를 사용한다. 초기 수집 결과를 원본으로 보존하고 재시도 파일을 별도로 남긴다. 제공된 역사 자료의 병합 원칙은 판독 성공한 재시도 결과로 실패 기록을 보완하는 것이다. 현재 시점의 새 결과를 과거 `data/`에 덮어쓰지 않는다.

## 약관

```bash
python collection/terms_collector.py --limit 5 --outdir collection_runs/terms_01
```

기본 입력은 `data/inputs/terms_sample.xlsx`다. 홈페이지 링크와 후보 경로에서 약관을 찾고, 키워드가 있는 문장을 추출한다. 새 폴더에 원문·CSV·엑셀 사본이 만들어진다. 자동 탐색·키워드 결과만으로 AI 학습 허용·제한·금지를 확정하지 않는다.

181개 최종 수작업 코딩표가 현재 배포 입력에 없으므로, 새 코딩 또는 기록 복구가 필요하다. 기본 재현 명령이 만드는 `results/reproduction/terms_coding_template.csv`에 최종 상태, 제3자 AI 학습 조항, 플랫폼 자체 AI 이용 조항, 근거 문장, 시점과 코딩자를 기록할 수 있다. 이 양식은 작업 보조용이며 자동 판정 결과가 아니다.

기존 엑셀의 `코딩북_변수정의` 시트를 기준으로 코드 의미를 먼저 확정하고, 해석이 갈리는 조항과 확인 불가 사례는 판정 근거를 따로 남긴다. 보존된 집계값 14·31에 맞추려고 개별 행의 코드를 추정해서는 안 된다.

## 검증 범위

이번 배포에서 수집기는 `--help`, import 시 부작용, 모의 HTTP 응답에 대한 처리와 출력·입력 보호를 검증했다. 실제 사이트를 새로 수집하지 않았다. 따라서 현재 사이트 접속 성공률이나 약관 탐색 성공률을 보장하는 테스트는 아니다.
