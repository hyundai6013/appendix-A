# 판정과 분석 규칙

## 분석 단위와 분모

`snapshot_allrows.csv`는 재시도 결과를 반영하고 공유 도메인을 원래 표본 행으로 다시 펼친 보존 파일이다. 도메인은 공백을 제거하고 소문자로 맞춘 뒤 최초 등장 행을 사용한다. 동일 도메인이 서로 다른 층에 있으면 먼저 나온 행의 층을 사용한다. 이는 기존 재판정 코드의 선택이며 다중 층 소속을 새로 모델링한 것이 아니다.

재판정은 저장 파일이 있으면 원문을 우선한다. 원문이 없고 `fetch_status=not_found`이면 파일 부재, 나머지는 판독 불가이다. 분석 분모는 원문 있음 882개와 파일 부재 73개를 합친 955개다. 판독 불가 121개를 미차단으로 세지 않는다. 빈 200 응답 파일과 404·410 파일 부재도 구분한다.

## 토큰과 루트 접근

초기 수집 15개 토큰에 `Perplexity-User`를 더한 16개를 사용한다. Protego의 `can_fetch(url, user_agent)`에 `https://{domain}/`를 넣어 루트 접근을 판정한다. 이 값은 실제 봇의 방문·학습 여부나 사이트 전체 콘텐츠에 대한 법적 허락을 뜻하지 않는다. `Google-Extended`와 `Applebot-Extended`는 독립 수집 봇이라기보다 이용 통제용 토큰이라는 점도 구분한다.

Protego의 API 인자 순서는 [프로젝트 문서](https://github.com/scrapy/protego)에 따른다. 배포본은 `protego==0.3.1`을 고정해 보존 결과와 대조한다. 원래 ZIP의 요구사항은 `protego>=0.3.1`뿐이어서 당시 정확한 설치 버전은 알 수 없다.

명시는 User-agent 값의 토큰이 대소문자를 무시하고 정확히 일치하는지 확인한다. 줄 끝 `#` 주석을 제거한 뒤 비교한다. 와일드카드에 따른 차단과 직접 명시는 서로 다르다. 주 분석은 직접 명시 192개를 사용하며, 수집 당시 메타데이터의 오래된 `explicit__*` 값을 그대로 쓰지 않는다.

## 5범주

| 상태 | 설계형 `cat5_primary` | 효과형 `cat5_effect` |
|---|---|---|
| 파일 부재 | ⑤파일부재 | ⑤파일부재 |
| 루트 접근 차단 | ①전체차단 | ①전체차단 |
| 루트 허용, 토큰 전용 그룹 하위 경로 제한 | ②부분차단 | ②부분차단 |
| 루트 허용, 비명시 토큰에 와일드카드 하위 경로 제한 적용 | ④무언급 | ②부분차단 |
| 토큰 명시, 제한 없음 | ③명시허용 | ③명시허용 |
| 토큰 비명시, 제한 없음 | ④무언급 | ④무언급 |
| 원문 확보 실패 | 원문없음, 분석 제외 | 원문없음, 분석 제외 |

하위 경로 판정은 원래 코드의 휴리스틱을 보존한다. Disallow 패턴에서 첫 `*` 앞부분을 취하고 끝의 `$`를 제거해 시험 경로를 만든다. 구체 경로를 만들 수 없는 패턴은 제한으로 기록한다. 따라서 모든 URL과 Allow 예외를 완전 탐색한 판정은 아니다. 이는 이번 정리에서 새로 채택한 규칙이 아니며, 다른 알고리즘으로 바꾸면 기존 결과와의 재현 여부를 별도로 검토해야 한다.

## 통계

층별 교차표에는 도메인마다 16종 중 하나라도 루트가 차단됐는지를 사용한다. Pearson 카이제곱, 조정 표준화 잔차와 Cramér V를 계산한다. 이항 로지스틱 회귀의 기준층은 ③ 공공·교육이다. 층 모형의 계수·표준오차·오즈비·Wald 신뢰구간·프로파일 우도 신뢰구간과 모형 적합도를 출력한다.

성숙도 보조모형은 원문 있음 882개만 사용한다. 저장 메타데이터의 `log(1+robots_bytes)`와 사이트맵 존재 여부를 사용한다. **원래 수집 코드의 `robots_bytes`는 디코딩한 문자열의 `len()`이므로 엄밀한 바이트 수가 아니다.** 이를 실제 파일 바이트 수로 다시 계산하지 않는다. 줄바꿈 정규화도 달라질 수 있어 보존 열을 사용한다.

민감도 분석은 루트 차단, 설계형의 루트·부분차단, 효과형의 루트·부분차단을 비교한다. ⑥층의 Fisher 비교는 보존된 `type`의 그룹A·B를 사용한다. 그룹A는 독립 도메인, 그룹B는 플랫폼 기반 호스팅의 사전 분류다. 이 구분을 실제 robots.txt 편집권의 조사 결과로 해석해서는 안 된다.

공유 도메인 분석은 중복 제거 전 1,199행으로 돌아간다. 169행은 공유 도메인에 연결된 표본 행 전체이고, 123은 고유 도메인으로 줄어들 때 제거되는 초과 행이다. 서로 다른 지표다. 주요 플랫폼별 판정은 원고의 표·그림과 같이 초기 15종을 사용한다.

기능군은 최종 원고 부록 B의 분석상 분류를 `crawler_groups.csv`에 옮긴 것이다. 9종 학습·5종 실시간·2종 검색의 토큰별 차단율을 평균한다. 이것은 해당 기능군을 하나라도 막은 사이트 비율이 아니다. Amazonbot·Diffbot 등의 당시 기능 배정 근거를 새로 검증한 결과로 제시하지 않는다.

## 응답 자료의 한계

원래 수집기는 HTTP 200이면 응답이 실제 robots.txt인지 별도로 검증하지 않았다. HTML로 시작하는 응답도 보존되어 있다. 이 저장소는 과거 판정을 재현하므로 이를 임의로 제외하지 않는다. 원본 응답은 HTTPS 본문을 UTF-8로 디코딩한 텍스트이며, 원시 HTTP 바이트·전체 헤더를 보존한 WARC가 아니다.

주석 제거는 Python 코드에만 적용했다. robots.txt에 있는 주석·경로·지시문은 관측 자료다. 공개용 마스킹 1건과 엑셀 개인 경로 메타데이터 제거는 [자료 계보](provenance.md)에 기록한다.
